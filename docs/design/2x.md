# javascript-excel 2.x: design proposal

Status: **proposal for review**. No code is written until this document is approved. It covers the 2.x row of the roadmap in [api.md §13](../api.md#13-roadmap-beyond-20), and follows that section's guardrails: the model grows only by optional fields, the writer's part list is open, format detection is a table, the reader can keep what it does not model, and formula text is always preserved.

Conventions are those of `api.md`: `[to verify]` marks an OOXML or Excel fact to be checked against ECMA-376 or a real file before code relies on it. Version numbers are the plan, not a commitment.

## 1. Summary and phases

| Phase | Adds | New parts written | Depends on |
|---|---|---|---|
| **2.1** | Lossless round trip: unmodelled parts and elements carried from `read()` to the writer. `.xlsm` write-back (VBA kept byte for byte), `.xltx`/`.xltm` output | whatever was preserved; `xl/vbaProject.bin` | 2.0 reader (`retainParts`), package registry |
| **2.2** | Data validation: lists/dropdowns, number/date/length rules, custom formulas, prompts and error alerts | none (sheet XML only) | 2.1 (element-level preservation of what 2.2 does not model) |
| **2.3** | Conditional formatting: the common rule types, with differential styles | none (sheet XML, `dxfs` in styles.xml) | 2.1, style registry |
| **2.4** | Notes (legacy comments): read and write. Threaded comments: read | `xl/commentsN.xml`, `xl/drawings/vmlDrawingN.vml` | 2.1 (VML is shared with form controls) |
| **2.5** | Images: read and write, with cell anchors | `xl/drawings/drawingN.xml`, `xl/media/imageN.*` | 2.1 (a drawing part is shared with charts and shapes) |

**Why this order.** Lossless round trip comes first, because every later phase must coexist with content it does not model:

- A sheet has **one** drawing part. Images (2.5) and preserved charts or shapes must share it.
- A sheet has **one** VML part. Notes (2.4) and preserved form controls must share it.
- Unmodelled conditional formats (2.3) and validations (2.2) must survive next to modelled ones.

Without 2.1, each feature phase would have to choose between dropping user content and refusing to write. Data validation is next because it is the smallest, with no new parts. Conditional formatting needs the style registry to learn `dxf`. Notes and images add parts and need the 2.1 merge rules.

Each phase is a **minor release** (§9.1): new optional model fields and options, new warning and error codes, and no change to existing output. A phase can ship on its own once its predecessors are in.

## 2. Cross-cutting constraints

These apply to every phase.

- **Plain data (§3.1).** New model fields are plain objects, arrays, strings, numbers, booleans, `Date`s and `Uint8Array`s, so workbooks still cross `postMessage`. No classes, handles or `WeakMap` side channels.
- **Reader output is writer input.** Every new field the reader fills is valid writer input, so `write(read(x))` keeps working. The conformance suite's fixpoint check (`docs/conformance.md`) extends to each phase.
- **The writer still never writes what it cannot validate**, with one deliberate exception: preserved parts (2.1) are passed through as bytes. They came from a file, they are size-checked, and they are never parsed for execution. Section 3.6 lists what that implies.
- **Security (§8).** Nothing new is executed or fetched. Preserved VBA is bytes. Preserved relationships to external targets keep `TargetMode="External"` and are never resolved. New untrusted inputs (images, VML) get size limits and format sniffing.
- **Cross-references into rebuilt parts are the hard part.** The writer rebuilds `workbook.xml`, `styles.xml`, `sharedStrings.xml`, worksheets and all `.rels`. Content that points *into* those by index (a conditional format's `dxfId`, a pivot cache's sheet references, `calcChain.xml`) cannot be carried as opaque bytes. Each phase says how its content is handled: modelled, carried with its reference rewritten, or dropped with a warning.

## 3. Phase 2.1: lossless round trip and macro/template write-back

### 3.1 Goal

`write(read(file, { preserve: true }))` keeps everything the model does not represent, as far as the dependency rules below allow:
- drawings, charts and shapes;
- VBA projects (including their signatures);
- custom XML parts;
- form controls, ActiveX and Excel tables;
- pivot tables and caches;
- slicers, timelines, sparklines (in `extLst`), the theme, and anything not yet known.

`.xlsm`, `.xltx` and `.xltm` can be written, so a macro-enabled workbook read and written back still runs its macros in Excel.

### 3.2 What 2.0 has

The reader's internal `retainParts` option returns the **bytes** of every zip part it did not parse, keyed by part name. That is necessary but not enough. A lossless writer also needs:

1. **The relationship graph** for preserved parts: which part points to which, with what type, id and target mode. The reader consumes sheet and workbook `.rels`, so today the edges into preserved parts are lost.
2. **The referencing elements** inside rebuilt XML, which the reader currently drops:
   - worksheet: `<drawing r:id>`, `<legacyDrawing r:id>`, `<legacyDrawingHF>`, `<picture>`, `<oleObjects>`, `<controls>`, `<tableParts>`, `<extLst>`;
   - workbook: `<extLst>`, `<pivotCaches>`, `<externalReferences>`, `<fileVersion>`.
4. **VBA code names.** They are *attributes* on elements the writer rebuilds: `sheetPr/@codeName` and `workbookPr/@codeName`. VBA modules refer to sheets and the workbook by code name (`Sheet1`, `ThisWorkbook`), so dropping them breaks macros after a round trip `[to verify: the exact failure in Excel]`. Element-level preservation cannot carry them; the model must.
3. **Content types** of preserved parts (defaults and overrides).

### 3.3 Model

```ts
// Reader output when ReadOptions.preserve is true; ignored (and not required) otherwise.
interface Workbook {
  /** Package content the model does not represent, carried to the writer unchanged. */
  preserved?: PreservedPackage | undefined;
}
interface Sheet {
  /** This sheet's preserved elements and the parts they reference. Moves with the sheet. */
  preserved?: PreservedSheet | undefined;
}

interface PreservedPart {
  /** Original part name, e.g. 'xl/vbaProject.bin', 'xl/charts/chart1.xml'. */
  name: string;
  contentType: string;
  data: Uint8Array;
  /** This part's own relationships (its .rels), with targets as written in the file. */
  rels?: PreservedRel[] | undefined;
}
interface PreservedRel {
  id: string;
  type: string;
  target: string;
  external?: boolean | undefined;
}

interface PreservedPackage {
  /** Workbook-level parts: VBA, custom XML, pivot caches, external links, ... */
  parts: PreservedPart[];
  /** Relationships from the workbook part to preserved parts. */
  workbookRels: PreservedRel[];
  /** Raw workbook.xml elements the model does not represent, keyed by their CT_Workbook position. */
  workbookElements: PreservedElement[];
  /** workbookPr/@codeName (VBA's ThisWorkbook). */
  codeName?: string | undefined;
  /** The workbook part's content type, so .xlsm/.xltx/.xltm round-trip. */
  workbookContentType: string;
}
interface PreservedSheet {
  /** Parts reached from this sheet: drawings, charts, VML, tables, pivot tables, ... */
  parts: PreservedPart[];
  /** Relationships from the worksheet part to those parts (ids as in the file). */
  rels: PreservedRel[];
  /** Raw worksheet elements the model does not represent, e.g. '<drawing r:id="rId2"/>'. */
  elements: PreservedElement[];
  /** sheetPr/@codeName, the sheet's VBA object name. */
  codeName?: string | undefined;
}
interface PreservedElement {
  /** Local name of the element in its parent's schema sequence, e.g. 'drawing', 'extLst'. */
  element: string;
  /** The element's XML, as read. */
  xml: string;
}
```

```ts
interface ReadOptions {
  /** Keep what the model does not represent so it can be written back. Default false. */
  preserve?: boolean | undefined;
}
interface WriteOptions {
  /** Package type. Default: the preserved workbook content type, else 'xlsx'. */
  format?: "xlsx" | "xlsm" | "xltx" | "xltm" | undefined;
  /** Write an .xlsx/.xltx without the preserved VBA project instead of throwing. Default false. */
  dropMacros?: boolean | undefined;
}
```

### 3.4 Writer behaviour

- **Part names.** Preserved parts keep their original names, so their internal relative targets (`../media/image1.png`) stay valid. A name that collides with a part the writer generates is renamed (`chart1.xml` → `chart1_1.xml`), and every relationship pointing to it is updated.
- **Relationship ids.**
  - Sheet `.rels` are rebuilt. Preserved relationships are re-added through the sheet's `Rels` builder, which already allocates `rIdN`.
  - Every `r:id`, `r:embed` and `r:link` attribute inside the sheet's preserved elements is rewritten from the old id to the new one. The rewrite is a namespace-aware attribute replacement on the element's XML, not a text search.
  - Workbook-level elements get the same treatment.
- **Element placement.** Preserved elements are emitted at their position in the CT_Worksheet or CT_Workbook sequence. The writer already emits elements in schema order, so this is one more slot list.
- **Code names** are written as `sheetPr/@codeName` and `workbookPr/@codeName` when preserved.
- **`dxf` carry-over (until 2.3 models conditional formats).** A preserved `<conditionalFormatting>` (or x14 rule) refers to `dxfs` by index. The reader keeps the referenced `dxf` XML with the fragment. The writer appends it to the new `dxfs` list and rewrites the `dxfId`.
- **Content types** come from the preserved parts (defaults and overrides) through the package registry.
- **Format.** `format` selects the workbook content type. The four content types are already in the reader's format table.
- **Macros.** If the preserved package contains `xl/vbaProject.bin` and `format` is `xlsx` or `xltx`, the writer throws `MACROS_NEED_MACRO_FORMAT` (new code) unless `dropMacros: true`. Without `format`, it infers `xlsm`/`xltm` from the preserved content type. `download()` names files by the caller, so the docs must tell callers to use the matching extension, because Excel refuses an `.xlsm` package with an `.xlsx` extension `[to verify]`.

### 3.5 What is dropped, with a warning

| Content | Why | Behaviour |
|---|---|---|
| `xl/calcChain.xml` | Refers to cells by sheet index; it is a cache that Excel rebuilds | Always dropped, no warning (Excel recalculates it) |
| Pivot tables and caches **when sheets are renamed, removed or reordered** | The cache definition names sheets and ranges | Kept if the sheet names they reference still exist; otherwise dropped with `PRESERVED_PART_DROPPED` |
| Preserved elements of a **removed sheet** | Belong to that sheet | Dropped with the sheet (no warning; the caller removed it) |
| Parts that reference `sharedStrings.xml` or `styles.xml` indices | Indices change when those parts are rebuilt | Dropped with `PRESERVED_PART_DROPPED` (none are known in common files `[to verify]`) |
| Raw `<conditionalFormatting>` that uses `dxfId` | Points into the rebuilt `dxfs` | Kept: the `dxf` is copied into the new `dxfs` and the `dxfId` rewritten (3.4). Modelled in 2.3 |

### 3.6 Risks

- **Stale content.** Preserved drawings, charts and comments are anchored to cells. If the caller inserts rows or edits values, they do not move or update, and charts keep their cached data until Excel recalculates. This matches what other non-Excel editors do. It is documented, not fixed.
- **Untrusted bytes in output.** Preserved parts are written without validation. A hostile file read with `preserve: true` and written back can carry hostile parts: VBA, external links, OLE objects. Mitigations:
  - `preserve` is opt-in;
  - the zip limits apply to preserved parts too;
  - the writer refuses VBA in a non-macro format;
  - preserved external relationships are listed in `ReadResult.warnings` (`EXTERNAL_RELATIONSHIP_PRESERVED`), so an app can strip them.
- **Memory.** Preserved parts are held in the model. A workbook with large media keeps them all in memory twice during the write. Limits apply; streaming is out of scope.
- **Signed VBA.** `vbaProjectSignature.bin` (and the agile signature) is kept byte for byte. If anything else changes, Excel may report the signature as invalid. That is correct behaviour and is documented.

### 3.7 Will NOT do in 2.1

- Edit, parse or validate VBA, or create VBA projects.
- Fix up preserved content after edits (moving anchors, updating chart ranges, re-pointing pivot caches).
- Preserve content from `.xlsb`, `.ods` or `.xls` (no readers until 4.x).
- Preserve a part whose only reference is in a dropped element.
- Strict OOXML (§12 Q9) or Excel's "repair" of broken input.

## 4. Phase 2.2: data validation

### 4.1 Model

```ts
interface Sheet {
  validations?: DataValidation[] | undefined;
}
interface DataValidation {
  /** Cells it applies to: A1 ranges, e.g. ['B2:B100', 'D2']. */
  ranges: string[];
  type: "list" | "whole" | "decimal" | "date" | "time" | "textLength" | "custom" | "any";
  operator?: "between" | "notBetween" | "equal" | "notEqual" | "greaterThan" | "lessThan" | "greaterThanOrEqual" | "lessThanOrEqual" | undefined; // default 'between'
  /** Values or formulas. For 'list': an array of items, or a formula/range such as "=Lists!$A$1:$A$20". */
  list?: string[] | string | undefined;
  formula1?: string | number | Date | undefined;
  formula2?: string | number | Date | undefined;
  allowBlank?: boolean | undefined;      // default true
  /** Show the in-cell dropdown for lists. Default true. */
  dropdown?: boolean | undefined;
  prompt?: { title?: string | undefined; message: string } | undefined;
  error?: { style?: "stop" | "warning" | "information" | undefined; title?: string | undefined; message?: string | undefined } | undefined;
}
```

Builders: `LeafColumn.validation?: Omit<DataValidation, 'ranges'>` applies to the column's data range. `fromTable` maps nothing in 2.2.

### 4.2 OOXML

`<dataValidations count><dataValidation type operator allowBlank showDropDown showInputMessage showErrorMessage errorStyle errorTitle error promptTitle prompt sqref><formula1/><formula2/></dataValidation></dataValidations>` sits in CT_Worksheet after `conditionalFormatting` and before `hyperlinks`.

- **`showDropDown` is inverted:** `showDropDown="1"` **hides** the arrow `[to verify]`. The model uses the positive `dropdown`.
- **Inline lists** are written as `formula1` `"a,b,c"`, with quotes doubled. Excel caps an inline list at 255 characters `[to verify]`. Above that the writer throws `INVALID_VALIDATION` (new code) and suggests a range. Items containing a comma are rejected too, because Excel has no escape for them `[to verify]`.
- **Dates** in `formula1`/`formula2` are written as serials, using the workbook's date system.
- **Cross-sheet list sources** are written in the main element, which Excel 2010+ reads `[to verify]`. Validations that the reader finds only in `x14:dataValidations` (in `extLst`) are preserved raw by 2.1, not modelled.

### 4.3 Reader

It fills `sheet.validations` from `<dataValidations>`:
- inline list text becomes `list: string[]`;
- a list formula stays a string;
- unknown attributes are ignored.

### 4.4 Risks

- LibreOffice and Numbers support dropdowns but differ in prompt and alert display.
- Very large `sqref` lists (thousands of ranges) are bounded by the reader's limits.

### 4.5 Will NOT do

- Enforce validation when writing values: a cell may violate its own rule, as in Excel.
- The x14 extension forms (validations with formulas referencing other workbooks, IME modes), except preserved raw.
- Dropdowns from `<select>` in `fromTable` (a later minor, if asked).

## 5. Phase 2.3: conditional formatting

### 5.1 Model

```ts
interface Sheet {
  conditionalFormats?: ConditionalFormat[] | undefined;
}
interface ConditionalFormat {
  ranges: string[];
  rules: ConditionalRule[];
}
type ConditionalRule =
  | { type: "cellIs"; operator: CfOperator; formulas: [string | number] | [string | number, string | number]; style: CfStyle; stopIfTrue?: boolean }
  | { type: "expression"; formula: string; style: CfStyle; stopIfTrue?: boolean }
  | { type: "colorScale"; stops: Array<{ at: CfThreshold; color: Color }> }            // 2 or 3 stops
  | { type: "dataBar"; min: CfThreshold; max: CfThreshold; color: Color }               // basic bar, see 5.4
  | { type: "top10"; rank: number; bottom?: boolean; percent?: boolean; style: CfStyle }
  | { type: "aboveAverage"; below?: boolean; equal?: boolean; stdDev?: number; style: CfStyle }
  | { type: "duplicateValues" | "uniqueValues"; style: CfStyle }
  | { type: "containsText" | "notContainsText" | "beginsWith" | "endsWith"; text: string; style: CfStyle }
  | { type: "containsBlanks" | "notContainsBlanks" | "containsErrors" | "notContainsErrors"; style: CfStyle };
type CfOperator = "between" | "notBetween" | "equal" | "notEqual" | "greaterThan" | "lessThan" | "greaterThanOrEqual" | "lessThanOrEqual";
type CfThreshold = { type: "min" | "max" } | { type: "num" | "percent" | "percentile" | "formula"; value: number | string };
/** The differential style a rule applies: a subset of Style. */
type CfStyle = Pick<Style, "font" | "fill" | "border" | "numFmt">;
```

Rule order in the array is priority. The writer assigns `priority` 1..n across the sheet.

### 5.2 OOXML and styles

`<conditionalFormatting sqref><cfRule type priority dxfId operator stopIfTrue ...><formula/>...</cfRule></conditionalFormatting>` sits in CT_Worksheet after `phoneticPr` and before `dataValidations`. A rule's style goes into `<dxfs>` in styles.xml as a **differential** format: only the fields set.

The style registry gains a second list for `dxf`. It is deduplicated by normalised content like fonts, and is separate from `cellXfs`. Fills in a `dxf` follow Excel's convention, which puts a solid fill colour in `bgColor` `[to verify]`. This differs from cell fills, where it goes in `fgColor`, and the registry handles the difference.

Text rules (`containsText` and the others) also need their generated formula, for example `NOT(ISERROR(SEARCH("x",A1)))` for the range's top-left cell. The writer generates it, because Excel requires it `[to verify]`.

### 5.3 Reader

It reads rules into the model and `dxf` entries into `CfStyle`. Rule types not in the table (`iconSet`, `timePeriod`, x14 rules) are preserved raw by 2.1, and their `dxfId` is rewritten on write.

### 5.4 Risks

- `dataBar` and `iconSet` have Excel 2010+ extensions in `x14:conditionalFormattings` inside `extLst`, linked to the main rule by a GUID `[to verify]`. 2.3 writes only the 2007 form of `dataBar`; it renders as a gradient bar in Excel. The extended forms are preserved raw when read.
- LibreOffice renders most rule types. Numbers supports only some rules `[to verify]`, so the conformance checklist notes this.

### 5.5 Will NOT do

- Evaluate rules, or compute which cells a rule highlights (that is the viewer's render model, 3.x).
- Write icon sets, `timePeriod` rules or x14 extended data bars (preserved raw only).
- Pivot-table conditional formats.

## 6. Phase 2.4: comments and notes

Excel now has two features. **Notes** (the legacy "comments": a yellow box, `xl/commentsN.xml` plus VML) and **threaded comments** (Office 365 conversations, `xl/threadedComments/*` plus `xl/persons/person.xml`). Excel writes a legacy note next to each threaded comment as a fallback `[to verify]`.

### 6.1 Model

```ts
interface Cell {
  /** A legacy note (the yellow box). */
  note?: Note | undefined;
}
interface Note {
  text: string | RichText;
  author?: string | undefined;
  /** Shown permanently instead of on hover. Default false. */
  visible?: boolean | undefined;
  /** Box size in pixels at 96 dpi. Default about 144 x 79 (Excel's default) [to verify]. */
  size?: { width: number; height: number } | undefined;
}
interface Sheet {
  /** Threaded comments (read-only in 2.x): the reader fills this; the writer writes it back only through preservation. */
  threads?: CommentThread[] | undefined;
}
interface CommentThread {
  ref: string;
  comments: Array<{ id: string; author: string; date?: Date | undefined; text: string; resolved?: boolean | undefined }>;
}
```

The note lives on the cell, so builders and `fromTable` can attach it: an accessor may return `{ value, note }`. A note on an empty cell is a cell with `value: null`.

### 6.2 OOXML (write)

- **`xl/commentsN.xml`:** `<comments><authors><author/></authors><commentList><comment ref authorId><text>…rich text runs…</text></comment>`, related from the sheet with the comments relationship type.
- **`xl/drawings/vmlDrawingN.vml`:** one `v:shape` per note, anchored by `x:ClientData ObjectType="Note"` with `x:Row`/`x:Column` (zero-based) and `x:Visible` when visible. It's referenced by `<legacyDrawing r:id>` in the sheet. Excel does not show a note without its VML shape `[to verify]`. The VML is generated from a fixed template, with size and anchor computed from the model.
- **Content types:** the `vml` default (`application/vnd.openxmlformats-officedocument.vmlDrawing`) and the comments override.

### 6.3 Reader

- **Notes:** from `commentsN.xml`, with `visible` and `size` read from the VML when present.
- **Threads:** from `threadedComment*.xml`, with authors from `person.xml`. The legacy fallback notes Excel writes for threads are recognised (the thread id links them `[to verify]`) and not duplicated as notes.

### 6.4 Shared VML (depends on 2.1)

A sheet has one `<legacyDrawing>`, and its VML also holds form controls and some ActiveX shapes. On write, preserved VML shapes that are not notes are kept, and note shapes are regenerated, in one VML part. Shape ids are renumbered within the part `[to verify: whether Excel requires the o:spid / shape-type id ranges per sheet]`.

### 6.5 Risks

- VML is legacy and loosely specified. Excel is strict about the shape type declaration. The template must come from an Excel-made file and be checked in the JSE-9 manual check.
- Threaded comments written back unchanged keep working (2.1). If the caller edits the cells, threads stay where they were.

### 6.6 Will NOT do

- Write threaded comments, mentions or resolved state (read-only).
- Note box styling beyond size and visibility (fonts and colours of the box).
- Notes in `fromTable` from `title` attributes (possible later).

## 7. Phase 2.5: images

### 7.1 Model

```ts
interface Sheet {
  images?: SheetImage[] | undefined;
}
interface SheetImage {
  data: Uint8Array;
  /** Sniffed from the bytes on write; given by the reader. */
  type: "png" | "jpeg" | "gif";
  anchor: ImageAnchor;
  /** Alternative text (accessibility). Strongly recommended. */
  description?: string | undefined;
  name?: string | undefined;
  hyperlink?: Hyperlink | undefined;
}
type ImageAnchor =
  /** Moves and resizes with cells: corners at cells plus pixel offsets. */
  | { from: CellOffset; to: CellOffset }
  /** Moves with a cell, fixed size in pixels. */
  | { from: CellOffset; size: { width: number; height: number } }
  /** Fixed position on the sheet, in pixels from A1's top-left. */
  | { position: { x: number; y: number }; size: { width: number; height: number } };
interface CellOffset {
  cell: string;                                   // 'B2'
  offset?: { x: number; y: number } | undefined;  // pixels at 96 dpi
}
```

### 7.2 OOXML

- **Media:** `xl/media/imageN.{png,jpeg,gif}` with content-type defaults `image/png`, `image/jpeg` and `image/gif`. Identical images are stored once (deduplicated by hash).
- **Drawing:** `xl/drawings/drawingN.xml` is an `xdr:wsDr` with one anchor per image:
  - `xdr:twoCellAnchor`, `xdr:oneCellAnchor` or `xdr:absoluteAnchor`, containing `xdr:pic`;
  - `xdr:nvPicPr` with `cNvPr id name descr` (alt text) and an optional `a:hlinkClick`;
  - `xdr:blipFill` with `a:blip r:embed`, and `xdr:spPr`.
- Relationships go from the drawing to the media, and from the sheet's `<drawing r:id>` to the drawing.
- **Units:** offsets and sizes in EMU, 9,525 EMU per pixel at 96 dpi (914,400 per inch). Cell anchors use zero-based column and row with EMU offsets. One-cell and absolute anchors store their size directly (`xdr:ext`, EMU), so no column-width conversion is needed. A two-cell anchor's `to` corner is given as a cell plus offset.

### 7.3 Reader

- **Pictures:** every `xdr:pic` becomes a `SheetImage`, with the anchor converted back to cells and pixels.
- **Other anchors** (shapes, charts, group shapes, connectors) are kept as preserved anchor fragments (2.1).
- **Other formats:** pictures in formats the writer does not write (EMF, WMF, TIFF, BMP, SVG with its PNG fallback) are preserved, not modelled.

### 7.4 Shared drawing part (depends on 2.1)

A sheet has one drawing part.

- **On read:** the reader splits it into modelled pictures and preserved anchor fragments, each with the relationships it references (charts, images of unmodelled pictures).
- **On write:** the writer builds one drawing part. Anchor order is the preserved fragments' original z-order, with modelled images in their read position, and new images appended on top. `r:id`/`r:embed` in fragments are rewritten (3.4). `cNvPr/@id` values are renumbered to stay unique per drawing `[to verify]`.

### 7.5 Security and limits

- The writer sniffs PNG, JPEG and GIF signatures and throws `INVALID_IMAGE` (new code) when bytes and type disagree. It never trusts a caller's type.
- New option `WriteOptions.maxImageBytes`, with a proposed default `[placeholder, set in the 2.5 PR]`.
- Images are bytes. Nothing decodes them except for reading their pixel size, from the PNG/GIF header and JPEG SOF, when the anchor needs it.

### 7.6 Will NOT do

- Charts, shapes, text boxes, SmartArt or WordArt as model objects (3.x charts; others preserved only).
- Image editing (crop, rotation, effects), or in-cell pictures (Excel's `IMAGE()`/"place in cell", which is rich-value data `[to verify]`).
- SVG write, or EMF/WMF/TIFF/BMP write.
- Background images (`<picture>`) or header/footer images (`legacyDrawingHF`), which are preserved only.

## 8. Testing and conformance for 2.x

Each phase ships with the same layers as 2.0:

- **Unit tests** for the model, validation and exact XML.
- **Golden files read back by openpyxl:** it reads comments, validations, conditional formats and images, so per-feature checks are possible. VBA preservation is checked by comparing bytes.
- **LibreOffice:** open and re-save, then read back, in the existing job.
- **Our reader:** the round trip `write(read(x))` stays a fixpoint.
- **Fixtures written by Excel itself** for each feature, so the reader is tested on real output. These include an `.xlsm` with a signed VBA project, a sheet with a chart plus a picture, threaded comments, x14 data bars and icon sets.
- **Conformance corpus:** one workbook per phase (`20-validation`, `21-conditional`, `22-notes`, `23-images`, `24-round-trip.xlsm`). Each adds rows to `docs/conformance.md`, and the `[to verify]` items above are resolved by the manual check, as in JSE-9.

## 9. Open questions for review

Each has a recommendation; accepting it means no change to the text above.

**Q1. Preservation on by default?** *Recommendation:* opt-in (`preserve: true`). It costs memory, and it carries untrusted content (VBA, external links) into the output, so callers should ask for it. react-data-import does not need it; the viewer's save path will.

**Q2. Where preserved content lives.** In the model as plain data (`workbook.preserved`, `sheet.preserved`), or as an opaque handle kept outside the model. *Recommendation:* plain data, as designed. It survives `structuredClone` and the worker, it moves with its sheet when sheets are reordered or removed, and it is inspectable, for example to strip external links.

**Q3. VBA in a non-macro format.** *Recommendation:* throw `MACROS_NEED_MACRO_FORMAT` unless `dropMacros: true`. Infer `xlsm`/`xltm` when `format` is omitted. A silent drop would lose the user's macros, and silently switching the format would mismatch the file name.

**Q4. Fix-ups after edits.** Should the writer move preserved anchors and comments when rows are inserted? *Recommendation:* no, in 2.x. There is no "insert rows" operation in the model, and correct fix-ups need the formula engine (3.x). Document that preserved content stays where it was.

**Q5. Notes on the cell or on the sheet.** *Recommendation:* on the cell (`Cell.note`), as designed. It travels with the value through builders and `fromTable` hooks, and needs no ref bookkeeping. Threads stay sheet-level, because they are read-only.

**Q6. Threaded comments on write.** *Recommendation:* read-only in 2.x. When preserved and unchanged they are written back raw, otherwise they are dropped with `PRESERVED_PART_DROPPED`. Writing threads needs person ids and GUIDs; leave it to a later minor if asked.

**Q7. Conditional-format rule set in 2.3.** *Recommendation:* the table in 5.1 (cell value, expression, colour scales, 2007 data bars, top/bottom, above/below average, duplicates/unique, text rules, blanks and errors). It covers what spreadsheet exports use. Icon sets and x14 data bars are preserved raw and modelled in a later minor.

**Q8. Inline list limit.** *Recommendation:* throw `INVALID_VALIDATION` above Excel's limit (255 characters `[to verify]`) or for items containing commas, with a message suggesting a range source. A truncated dropdown would be silent data loss.

**Q9. Image units.** *Recommendation:* pixels at 96 dpi in the API, with EMU kept internal, the same unit as `{ wpx }` widths. Cell anchors (`from`/`to`) are the default, because that is how users place images over data.

**Q10. Image formats.** *Recommendation:* write PNG, JPEG and GIF only, and model only those on read. Every other format is preserved. SVG (with its PNG fallback) is a later minor.

**Q11. One release per phase, or one 2.1 with everything.** *Recommendation:* one minor per phase (2.1–2.5), each with its own conformance file and manual-check rows. Phases 2.2 and 2.3 are small and could ship together if review time is short.

**Q12. New error and warning codes.**
- Errors: `MACROS_NEED_MACRO_FORMAT`, `INVALID_VALIDATION`, `INVALID_CONDITIONAL_FORMAT`, `INVALID_NOTE`, `INVALID_IMAGE`.
- Warnings: `PRESERVED_PART_DROPPED`, `EXTERNAL_RELATIONSHIP_PRESERVED`.

*Recommendation:* add them in their phases. New codes are minor (§9.1).
